# AGENTS.md

Provider for RcodeZero (<https://www.rcodezero.at/>), Anycast DNS by nic.at. REST API v2 with an OpenAPI spec; client and mock are generated from it. Status: v0.1.0, zones only.

## Stack

- Go: see `go.mod`.
- Framework: `terraform-plugin-framework` (see `go.mod` for pinned version).
- Registry: `registry.terraform.io/dg-i/rcodezero`.
- Codegen: `oapi-codegen` and `tfplugindocs`, both as `tool` in `go.mod`; run via `make generate`.

## API

- Base URL: `https://my.rcodezero.at` (provider attribute `endpoint`).
- Auth: `Authorization: Bearer <token>`. The token comes from the provider block only, never from the environment (deliberate).
- Spec: `api/rcode0api-2.11.json`, vendored unchanged. Fixes go into `api/overlay.yaml`, never into the spec.
- Generated code covers only `AddZone`, `GetZoneDetails`, `UpdateZone`, `PatchZone`, `DeleteZone` (`include-operation-ids` in `api/*.cfg.yaml`). New operations: add them to both configs, then `make generate`.

## Resources

| Resource | Operations | Import format |
|---|---|---|
| `rcodezero_zone` | `POST /api/v2/zones`, `GET/PUT/PATCH/DELETE /api/v2/zones/{zone}` | domain |

## Layout

```
api/                  # vendored spec, overlay, oapi-codegen configs
internal/
  rcode0api/          # generated client (client.gen.go) — do not edit
  mockserver/         # generated strict server (api.gen.go) + in-memory impl (server.go)
  provider/           # provider, zone resource, parseResponse, logging transport
  acceptance/         # tofu-driven tests against the mock (TF_ACC=1)
cmd/mock-rcodezero/   # standalone mock for manual runs
docs/                 # generated by tfplugindocs — do not edit
examples/             # registry examples (provider/, resources/) + dev/ for the mock
```

## Workflow

See `CONTRIBUTING.md` for build/test/lint commands. Additional rules:

- After any change to the schema, `examples/` or `api/`: `make generate` and commit the result. CI (`verify_generated`) fails otherwise.
- Acceptance tests need `tofu` in `PATH` (TestMain sets `TF_ACC_TERRAFORM_PATH` and `TF_ACC_PROVIDER_HOST=registry.opentofu.org`). No credentials.
- API behavior the spec doesn't document goes into the mock or a fault in `internal/acceptance/main_test.go`, with the date it was verified against the real API.

## Gotchas

Things the real API does that the spec doesn't say (all verified against the real API, see comments in code).

### Error responses are undocumented

The spec has no error responses; `api/overlay.yaml` adds `{"status":"failed","message":...}`. Auth errors don't follow that shape. `parseResponse` (`internal/provider/api.go`) checks the HTTP status before handing the body to the generated parser, otherwise a 404 or the real status would be hidden behind a decode error.

### `status: failed` with HTTP 2xx

Some errors come back with the expected 2xx status and `{"status":"failed"}` in the body (seen for PATCH `zone_disabled` on a slave zone). `parseResponse` checks 2xx bodies for that too.

### `serial_auto_increment` is omitted for slave zones

The overlay removes it from `ZoneDetails.required`, so it is generated as `*bool`. `ModifyPlan` predicts it when unconfigured: null for slave, unknown after a type change (`UseStateForUnknown` alone would carry the old value over).

### `zone_disabled` only works on master zones

`Update` re-enables before a possible switch to slave and disables only after a possible switch to master. `ValidateConfig` rejects `disabled = true` on slave zones.

### Create must store state before follow-up calls

After `AddZone` succeeds the zone exists; state is set before the optional PATCH, so a failing PATCH taints the resource instead of orphaning the zone.

### `domain` must be canonical

Lower case, no trailing dot (validator). `domain` forces replacement, so any other spelling would destroy and recreate the zone. Import normalizes `Example.AT.` to `example.at`.
