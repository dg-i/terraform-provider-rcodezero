# Contributing to terraform-provider-rcodezero

Thanks for your interest in improving the Terraform Provider for RcodeZero.
This document covers how to set up a development environment, run tests, and
submit changes.

## Requirements

- Go (see `go.mod` for the version)
- OpenTofu >= 1.6 in `PATH` for the acceptance tests and local end-to-end testing
- No RcodeZero account needed: all tests run against an in-process mock

## Layout

| Path | Content |
|---|---|
| `api/rcode0api-2.11.json` | Vendored RcodeZero OpenAPI spec (unchanged copy of `rcode0api-latest.json`) |
| `api/overlay.yaml` | Fixes applied before code generation (error responses, optional fields) |
| `api/*.cfg.yaml` | oapi-codegen configs: client and mock server, both limited to the zone operations |
| `internal/rcode0api` | Generated API client |
| `internal/mockserver` | Generated server stubs + in-memory implementation; validates every request against the spec |
| `internal/provider` | Provider and `rcodezero_zone` resource, with unit tests |
| `internal/acceptance` | tofu-driven tests against the mock (`TF_ACC=1`) |
| `cmd/mock-rcodezero` | Mock as a standalone server for manual tofu runs |
| `docs/` | Generated by tfplugindocs (`make generate`) |
| `examples/provider`, `examples/resources` | Registry examples, rendered into `docs/` |
| `examples/dev` | Config for manual runs against the mock |

## Development workflow

```bash
make generate   # Regenerate API client + mock from api/, and docs/ from the schema
make build      # Build bin/terraform-provider-rcodezero
make test       # Unit tests
make testacc    # tofu-driven tests against the in-process mock
make lint       # golangci-lint
```

Generated code and `docs/` are committed; CI fails if they don't match
`make generate`. After any schema change, also re-check `README.md` (the
manual examples there are not regenerated).

### Local end-to-end testing against the mock

In two terminals:

```sh
# terminal 1 (blocks)
make mock                                   # listens on 127.0.0.1:8080, token "mock-token"

# terminal 2
make build
cd examples/dev
TF_CLI_CONFIG_FILE=$PWD/dev.tofurc tofu apply -var-file=mock.tfvars
```

`dev.tofurc` uses `dev_overrides` pointed at `bin/`, so no `tofu init` is needed.

### Acceptance tests

```bash
make testacc
```

They run real `tofu` commands against the in-process mock and need no
credentials. Use the fault hooks in `internal/acceptance/main_test.go` to
simulate API behavior the spec doesn't document.

## Branching and commits

- Branch from `main`. PRs target `main`.
- Keep commits focused — separate refactors, features, and fixes.
- Run `make test testacc lint` before pushing.

## Submitting a pull request

1. Fork the repo and create a topic branch.
2. Make your changes with tests where applicable.
3. Run `make test testacc lint` and, if you changed the schema, examples or `api/`, `make generate`.
4. Open a PR using the template. Describe the change and link any issue.
5. CI will run build, unit tests, acceptance tests, lint, govulncheck and the generated-code check.

## Reporting bugs

Use the issue template. Include a minimal Terraform/OpenTofu config that
reproduces the problem, the provider version, and the full error output.

## Security issues

See [SECURITY.md](SECURITY.md) — please do not file public issues for security
problems.
